# Маршрутизация

Это проектная документация API MVP для PHP 8.5+. Реализация ещё не готова; namespace `PhpHono` предварительный. [Оглавление документации](README.md).

## Первый маршрут

Маршрут связывает HTTP-метод и путь с обработчиком. Обработчик получает Context и возвращает PSR-7 Response.

```php
use PhpHono\Context;
use PhpHono\Hono;
use Psr\Http\Message\ResponseInterface;

$app = new Hono();
$app->get('/hello', fn (Context $c): ResponseInterface => $c->text('Hello'));
```

Разделы ниже — независимые примеры, а не один файл для последовательного копирования. В них `$app` означает новый экземпляр Hono, а `Context` и `ResponseInterface` — импорты из первого примера. Все маршруты нужно зарегистрировать до обработки первого запроса.

## HTTP-методы

Для обычных методов предусмотрены `get`, `post`, `put`, `patch`, `delete` и `options`. Метод `query` регистрирует HTTP-метод QUERY; query string читается через `$c->req->query()`.

```php
$app->post('/messages', fn (Context $c): ResponseInterface =>
    $c->json(['accepted' => true], 202)
);

$app->on(['GET', 'POST'], ['/ping', '/health'],
    fn (Context $c): ResponseInterface => $c->text('ok')
);

$app->all('/maintenance', fn (Context $c): ResponseInterface =>
    $c->text('Maintenance', 503)
);
```

`on()` принимает строку или массив методов и путей. Имена методов приводятся к uppercase. `all()` регистрирует обработчик для любого метода. Во всех вызовах путь передаётся явно: формы, использующей путь предыдущего вызова, в PHP API нет.

## Параметры пути

```php
$app->get('/users/:id', fn (Context $c): ResponseInterface =>
    $c->json(['id' => $c->req->param('id')])
);

$app->get('/hello/:name?', fn (Context $c): ResponseInterface =>
    $c->text('Hello, ' . ($c->req->param('name') ?? 'guest'))
);

$app->get('/orders/:id{[0-9]+}', fn (Context $c): ResponseInterface =>
    $c->json(['orderId' => $c->req->param('id')])
);
```

Для `/users/42` параметр `id` — строка `'42'`. Типы нужно проверять и преобразовывать на границе приложения. `$c->req->param()` без имени возвращает карту параметров текущего совпавшего обработчика; отсутствующий одиночный параметр даёт `null`.

Необязательным может быть только последний сегмент. Regex применяется внутри одного сегмента: `[0-9]+` подходит, переход через `/`, lookaround и backreferences не поддерживаются. При повторяющемся имени, например `/:id/:id`, сохраняется первое значение; понятнее использовать разные имена.

Параметры декодируются после сопоставления маршрута. `%2F` не превращается заранее в границу сегмента. Не декодируйте параметры второй раз в обработчике. Подробнее — [Request](request.md).

## Поддерживаемые шаблоны

| Шаблон | Совпадения |
| --- | --- |
| `/` | Только корневой путь |
| `/about` | Точный путь с учётом регистра |
| `/users/:id` | Один обязательный сегмент |
| `/hello/:name?` | `/hello` и `/hello/Ada` |
| `/orders/:id{[0-9]+}` | Числовой сегмент |
| `*` или `/*` | Любой путь |
| `/api/*` | `/api`, `/api/`, `/api/users`; не `/api2` |

В MVP не поддерживаются wildcard внутри пути (`/a/*/b`), suffix wildcard (`/assets*`), несколько optional segments и regex через несколько сегментов. Неподдерживаемый шаблон должен приводить к ошибке регистрации, а не работать приблизительно.

Query string не участвует в выборе маршрута: `/search?q=php` сопоставляется с `/search`. По умолчанию `/about` и `/about/` различаются (`strict=true`). Режим `strict=false` удаляет один завершающий `/` входного пути, кроме корня, и не делает redirect. Способ передачи constructor options пока не закреплён в спецификации.

Для длины path предусмотрен предел 8192 bytes по умолчанию, превышение даёт 414. Некорректное percent encoding или UTF-8 в пути/query даёт 400.

## Порядок регистрации

Совпавшие маршруты и middleware выполняются в порядке регистрации. Статический путь не получает автоматического преимущества перед параметрическим.

```php
$app = new Hono();

$app->get('/users/new', fn (Context $c): ResponseInterface =>
    $c->text('New user form')
);

$app->get('/users/:id', fn (Context $c): ResponseInterface =>
    $c->text('User ' . $c->req->param('id'))
);
```

Для `/users/new` первый обработчик возвращает ответ и завершает цепочку. Если поменять объявления местами, параметрический обработчик вернёт `User new`. Для передачи управления следующему совпадению нужно вызвать `$next()` — см. [middleware](middleware.md).

Каждый обработчик видит параметры своего шаблона. Глобальный middleware `'*'` не получает заранее параметры `:id` из следующего endpoint.

## Группы маршрутов

`route()` добавляет уже зарегистрированные маршруты дочернего приложения под префиксом:

```php
$users = new \PhpHono\Hono();
$users->get('/', fn (Context $c): ResponseInterface => $c->json([]));
$users->get('/:id', fn (Context $c): ResponseInterface =>
    $c->json(['id' => $c->req->param('id')])
);

$app->route('/users', $users);
```

Сначала завершите настройку `$users`, затем вызовите `route()`. Позднее добавленные маршруты child не появятся у родителя автоматически. Дочерний `onError` сохраняется при импорте, а для `notFound` используется обработчик корневого приложения.

`basePath()` создаёт представление общей таблицы маршрутов с префиксом:

```php
$api = $app->basePath('/api');
$api->get('/status', fn (Context $c): ResponseInterface => $c->json(['ok' => true]));
$app->get('/status', fn (Context $c): ResponseInterface => $c->text('ok'));
```

Получаются `/api/status` и `/status`. Префикс исходного `$app` не меняется. Таблица общая: первый dispatch через любое представление закрывает её для последующей регистрации.

## HEAD, OPTIONS и несовпавший метод

HEAD использует цепочку GET, сохраняет `$c->req->method() === 'HEAD'` внутри обработчика и возвращает наружу ответ без тела. Отдельный `on('HEAD', ...)` не выбирается: это выбранное поведение Hono v4. Не выполняйте побочные изменения данных в GET-обработчиках, предполагая, что HEAD их не вызовет.

Если путь существует только для GET, POST к нему по умолчанию получает 404. Автоматический 405 запланирован как отдельный opt-in middleware версии 1.0. OPTIONS нужно зарегистрировать явно либо поручить CORS middleware; универсальный OPTIONS-ответ ядро не создаёт.

Настройка ответа 404 описана в [обработке ошибок](errors.md). Вызов маршрутов без сервера — в [тестировании](testing.md).
