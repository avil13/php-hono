# PHP Hono

PHP Hono — проект HTTP-фреймворка для **PHP 8.5+** с маршрутизацией и middleware в стиле Hono. Обработчик получает Context и возвращает PSR-7 Response; приложение можно вызывать в памяти или подключать к HTTP-серверу через адаптер.

**Статус: проектная документация.** На 2 ноября 2026 года в репозитории есть спецификация, но ещё нет реализации, `composer.json` и готового пакета. Примеры показывают целевое использование API MVP. Namespace `PhpHono` предварительный. Их можно использовать для обсуждения и реализации контракта; запуск станет возможен после появления библиотеки.

```php
use PhpHono\Context;
use PhpHono\Hono;

$app = new Hono();
$app->get('/', fn (Context $c) => $c->text('Hello, PHP Hono!'));
$app->get('/users/:id', fn (Context $c) =>
    $c->json(['id' => $c->req->param('id')])
);
```

## Основные правила

- Каждый запрос получает новый Context. Данные текущего запроса храните через `set/get/has`; типизированные объекты получайте через `extension(Type::class)`, не через глобальные переменные.
- Готовые handlers/middleware собираются через constructor DI; необязательный PSR-11 контейнер используется только при bootstrap. В ядре нет autowiring или service locator.
- Обработчик возвращает Response. Middleware либо возвращает ранний Response, либо вызывает `$next()` ровно один раз.
- Регистрация маршрутов заканчивается до первого запроса. После начала dispatch таблица маршрутов замораживается.
- `request()` выполняет приложение в памяти. `handle()` принимает PSR-7 ServerRequest. Ни один из этих методов сам не отправляет ответ в сеть.
- Готовые сторонние PSR-15 middleware входят в обязательный MVP и подключаются через `Psr15::wrap()`; [пример и ограничения](middleware.md#psr-15-middleware).
- JSX и WebSocket исключены из проекта. HTML-ответы остаются; HTTP streaming/SSE запланированы отдельно для 1.0.

## Что ещё не закреплено

Имя Composer-пакета, сигнатуры конструктора конфигурации, SAPI bootstrap/emitter, фабрики встроенных middleware и конструктор `HttpException` будут уточнены при реализации. Руководство не подменяет их выдуманными командами и методами: готовые примеры используют уже описанный публичный контракт.

Возможности 1.0 помечены отдельно и не входят в MVP. Источник проектных решений — [спецификация](../spec/02-specification.md); порядок реализации — [план задач](../spec/04-roadmap.md). Эта документация описывает использование, а не подтверждённую тестами совместимость выпущенной библиотеки.
