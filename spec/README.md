# PHP Hono: спецификация и план

Статус: проект плана, реализация не начата. Обновлено: 2 ноября 2026 года.

Цель — самостоятельный PHP-фреймворк с привычным API и проверяемым поведением HTTP-ядра Hono. Минимальная версия **PHP 8.5** — требование пользователя. **Поддержка готовых сторонних PSR-15 middleware обязательна уже в MVP. JSX и WebSocket исключены из проекта по решению пользователя**, включая будущий backlog. Это не официальный порт и не обещание совместимости со всей JavaScript-экосистемой Hono.

Исходная точка: репозиторий `php-hono` пуст, существующих контрактов и зависимостей нет. Исследован Hono **4.13.16**, commit [`c91b60a251186fb024557c6d55a11d8e388f179c`](https://github.com/honojs/hono/tree/c91b60a251186fb024557c6d55a11d8e388f179c). Версия взята из `package.json` этого коммита, а не из обновляемой документации.

## Предлагаемый объём

- **MVP / 0.1:** HTTP-ядро, routing, middleware, PSR-15 bridge для сторонних пакетов, Request/Context с типизированными extensions, constructor injection и необязательная внешняя PSR-11 сборка, ответы, ошибки, формы с явно ограниченным multipart, SAPI/FPM, тестирование без сервера и базовые middleware.
- **1.0:** дополнительные HTTP middleware, static files, streaming/SSE, один worker adapter и стабилизация публичного контракта.
- **После 1.0:** отдельные направления без обязательства реализовать их все: JWT/JWK, расширенный multipart, другие runtimes, cache, RPC/codegen и прочие helpers.

Всего в основном плане **32 задачи**. Оценка: **31–55 человеко-дней до MVP**, **48–87 до 1.0 суммарно**; с резервом 25% — **39–69** и **60–109** соответственно. T21 перенесена из этапа 1.0 в MVP с сохранением ID и оценки 2–3 дня. 2 ноября T06 расширена типизированным Context и DI-примерами (+1 день по обеим границам), T01 — Mago и проверкой staged snapshot (+1 день к верхней границе), без новых задач. Это предварительная оценка разработки, проверки и документации, а не обещание календарного срока. Полный функциональный паритет с upstream в неё не входит.

## Принятые для планирования решения

PHP 8.5+, Composer, PSR-4, PSR-7/17 на HTTP-границе, синхронный Hono-style middleware, PHP-FPM и встроенный PHP server для MVP. Один простой router; оптимизации после измерений. Для 1.0 предлагается FrankenPHP worker mode как первый постоянный процесс.

Расширение Context — через собственные объекты состояния и `extension(class-string)`, зависимости handlers — через конструкторы. Внешний PSR-11 container допускается при сборке приложения; собственный контейнер и resolver не требуются. [Руководство и примеры](../docs/context-extensions.md).

Mago 1.59.0 — выбранный formatter/linter со строгими правилами; PHPStan max проверяет типы. В T01 входят read-only pre-commit по staged snapshot и те же проверки в CI. [Разработка и проверки](../docs/development.md).

PHP 8.5, поддержка сторонних middleware, исключение JSX/WebSocket, расширяемый Context с DI-подходом и строгие Mago/pre-commit проверки согласованы пользователем. Остальные детали остаются проектными решениями для планирования. Имя Composer-пакета и окончательный namespace уточняются перед публикацией; в примерах используется `PhpHono`.

Начинать реализацию следует с T01 и T02. Сначала закрепить профиль совместимости и эталонные сценарии, затем создавать ядро. План в `spec` и руководство в `docs` пока описывают целевой API; реализации ещё нет.
